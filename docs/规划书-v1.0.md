# 智能竞品情报分析 Agent 项目开发规划书

项目代号：CrawlerAgent
版本：v1.0（纯文字版）
编制日期：2026年8月15日
开发环境：VSCode + Python 3.10 及以上，操作系统不限

## 一、项目背景与目标

### 1.1 项目背景

在商业分析、市场调研、产品策划等日常工作中，经常需要快速收集并提炼网络上关于竞争对手、行业动态或特定产品的公开信息。传统方式依赖人工搜索、阅读和整理，不仅耗时费力，而且难以覆盖多来源、多角度，容易遗漏关键信息。借助大语言模型和智能体技术，可以构建一套自动化的情报收集与智能分析系统，显著提升信息获取与决策支撑效率。

### 1.2 项目最终目标

开发一个基于大语言模型的竞品情报分析智能体。用户只需输入一个公司名称或产品名称，该智能体即能自主完成以下完整工作流：

1. 根据关键词自动搜索相关新闻、报道或评论；
2. 抓取多篇网页的完整正文内容；
3. 对抓取的文本进行深度阅读和提炼；
4. 最终输出一份结构清晰、带有引用来源的竞争态势分析报告（以 Markdown 格式呈现）。

### 1.3 核心设计哲学

- 迭代演进：从最简单可用的版本起步，每两周增加一项核心能力，不追求一次性完成所有功能。
- 模块化组织：将工具函数、智能体逻辑、多角色协作层明确分离，便于后续维护和扩展。
- 低成本实验：全程利用阿里云百炼平台的免费调用额度，在开发阶段无需额外资金投入。

## 二、技术栈确认

- 大语言模型：选用阿里云百炼平台提供的 qwen‑plus 模型。理由是免费额度充足，且该模型的工具调用能力稳定可靠。
- API 调用方式：采用 OpenAI 接口兼容模式。该模式是当前最成熟的调用方式，工具调用解析无已知缺陷，也便于未来更换其他模型服务。
- 编程语言：使用 Python 3.10 及以上版本。Python 是智能体开发社区的主流语言，相关库和示例丰富。
- 集成开发环境：选择 Visual Studio Code。该 IDE 轻量、插件生态强大，调试 Python 代码十分便利。
- 虚拟环境与包管理：使用 uv 工具。uv 替代了传统的 pip + venv + requirements.txt，运行速度更快，依赖管理更简明。
- 核心第三方库：包括 openai（API 调用）、python-dotenv（环境变量管理）、requests（网络请求）、beautifulsoup4（网页解析）。这些是完成基础网络请求和 HTML 解析的必要组件。

## 三、四阶段开发路线图

### 阶段一：基础设施搭建（预计用时 1 天）

目标：在本地电脑上完成项目初始化，确保能够通过百炼平台成功调用一次大模型，并得到正常回复。

1. 在电脑上创建项目文件夹，使用 uv 工具进行项目初始化。
2. 通过 uv 安装所有必需的第三方依赖库。
3. 在项目根目录下创建环境变量配置文件，用于存放百炼的 API 密钥。
4. 编写一个极简的测试脚本，该脚本通过百炼的兼容接口调用 qwen‑plus 模型，并打印出模型的自我介绍。

验收标准：在终端中运行测试脚本后，能够看到模型返回的自然语言回复，证明网络连通和密钥有效。

### 阶段二：V0.0 版本 – 赋予智能体工具调用能力（预计用时 1 周）

目标：实现最基本的“工具调用”闭环，使智能体能够根据用户的自然语言指令，主动调用本地编写的工具函数来完成实际操作。

1. 创建一个专门存放工具函数的模块，在其中定义两个最基本的工具：
   - 获取当前系统时间的工具（无参数，返回时间字符串）；
   - 根据给定网址抓取网页标题或正文的工具（使用网络请求库和 HTML 解析库）。
2. 编写智能体主循环脚本，在该脚本中：
   - 将上述工具的定义以特定格式传递给模型接口；
   - 解析模型返回的调用请求，识别出需要调用的工具名称和参数；
   - 本地执行对应的工具函数，获得执行结果；
   - 将执行结果再传回模型，让模型基于真实结果给出最终答复。

验收标准：当用户输入“帮我抓取百度首页的标题”时，智能体不会凭空编造，而是真实调用抓取工具，并返回“百度一下，你就知道”之类的正确结果。

### 阶段三：V1.0 版本 – 引入计划、记忆与多步推理（预计用时 2 周）

目标：将智能体从“一问一答”升级为能够自主规划步骤、进行多轮思考的 ReAct 模式，使其能够处理更复杂的复合指令。

1. 将主循环改造为迭代式循环，每次迭代包含“思考 → 行动 → 观察”三个环节，并允许循环多次，直到智能体认为自己已获取足够信息为止。
2. 设置安全防护机制，例如最大迭代次数和超时限制，防止程序陷入死循环。
3. 利用对话消息列表的累积来维持整个任务过程中的短期记忆，使智能体能基于之前获取的信息进行后续推理。
4. 增加简单的容错逻辑，例如当某个网页抓取失败时，引导智能体尝试其他链接或给出友好提示。
5. 在终端打印出每步的思考过程和行动细节，方便开发者调试和理解智能体的行为逻辑。

验收标准：当用户输入“请搜索关于‘百炼平台’的最新新闻，抓取其中两篇文章，并总结它们的核心观点”时，智能体能够自动完成搜索、抓取、总结全过程，并在终端输出清晰、可追溯的推理链条。

### 阶段四：V2.0 版本 – 多角色协同与高质量报告生成（预计用时 2 周）

目标：不再依赖单个智能体完成所有工作，而是引入多个具有不同职责的智能体，通过角色分工和协作，生成更严谨、更深入的分析报告。

1. 在项目中新增一个多智能体协作包，在其中创建三个独立的智能体实例（它们共用同一个大模型服务，但各自拥有不同的系统提示词）：
   - 研究员智能体：只负责从抓取的文本中提取客观事实，不加入任何主观评价；
   - 分析师智能体：基于研究员提供的事实，进行优劣势、机会威胁等竞争态势分析；
   - 审查员智能体：核对分析师的结论是否都能在原始材料中找到证据，以减少模型幻觉。
2. 定义一种简单的结构化数据格式，用于在三个智能体之间传递信息，使它们能够依次接力工作或进行交叉验证。
3. 最终整合所有产出，生成一份包含标题、分节内容、结论和引用来源的完整报告，并保存为 Markdown 文件。

验收标准：输入一个完整的分析课题（例如“分析字节跳动旗下豆包与阿里通义千问的竞争态势”），系统能够输出一份逻辑清晰、证据扎实、并带有来源链接的分析报告。

## 四、里程碑与可交付成果

- 里程碑 M0（第 1 天结束）：百炼模型调用测试成功，环境配置完成。
- 里程碑 M1（第 1 周末）：V0.0 版本智能体可运行，支持单一工具调用。
- 里程碑 M2（第 3 周末）：V1.0 版本智能体可运行，支持多步推理和记忆。
- 里程碑 M3（第 5 周末）：V2.0 版本智能体可运行，能生成多角色协作的结构化报告。

## 五、最终项目目录结构（文字描述）

项目根目录下将包含以下主要内容：

1. 由 uv 自动管理的虚拟环境目录（不纳入版本控制）；
2. 环境变量配置文件（存放 API 密钥，不纳入版本控制）；
3. 项目忽略文件（用于排除虚拟环境、缓存文件和敏感配置）；
4. 项目元数据配置文件（记录项目名称、依赖信息等）；
5. 依赖锁定文件（锁定所有库的精确版本）；
6. 连通性测试脚本（阶段一产物）；
7. 工具函数模块（阶段二产物）；
8. 单工具调用智能体脚本（阶段二产物）；
9. 多步推理智能体脚本（阶段三产物）；
10. 多角色协作子目录（阶段四产物），其中包含各角色的定义和协同逻辑。

## 六、风险与应对策略

- 风险：百炼免费额度提前耗尽。应对：每次调用后记录 Token 消耗，优化提示词长度，必要时评估是否切换为更低成本的模型或进行小额充值。
- 风险：工具调用时模型返回格式不标准。应对：在代码中增加异常捕获和自动重试机制，同时可在提示词中加强对输出格式的要求。
- 风险：目标网站反爬虫导致抓取失败。应对：为请求添加常见浏览器标识，适当增加请求间隔，若仍失败可考虑使用模拟浏览器工具或更换数据源。
- 风险：智能体陷入无限循环。应对：严格设置最大迭代次数，并增加日志记录便于分析原因，后续可优化决策逻辑。

## 七、未来扩展方向（V3.0 及以后）

1. 引入向量数据库，实现长期记忆和基于历史文档的检索增强生成。
2. 集成更多实用工具，如发送邮件、导出 PDF、自动生成 PPT 等。
3. 开发友好的 Web 操作界面，或将智能体封装为标准的 API 服务。
4. 支持多格式输入，如直接上传 PDF、Word 或图片文件进行分析。

本规划书作为项目启动的指导文件，所有阶段的推进应遵循“先跑通、后优化”的原则，每周回顾进度并灵活调整。
