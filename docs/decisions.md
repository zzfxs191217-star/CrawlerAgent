## D-012 验收修复：正文抽取、表格转义、导出防御与搜索排序

- 日期：2026-08-15
- 背景：V3.2 验收发现三类问题：①PDF 导出失败——标题含 `|` 导致资料清单表格列数错乱，reportlab 布局报 negative availWidth；②网页正文混入大量导航噪音，研究员难以提炼事实；③RSS 候选仅按日期排序，无关文章淹没有效结果（两次验收报告出现“无事实条目”）。
- 决策：
  1. `crawler/tools/web.py`：正文抽取优先定位内容容器（`article`/常见正文选择器），失败回退整页；
  2. `crawler/multi_agent/orchestration.py`：Markdown 表格单元格中的 `|` 转义为全角 `｜`；
  3. `crawler/export.py`：表格行归一化（补齐列数）+ 显式等分列宽，杜绝负宽度；
  4. `crawler/tools/search.py`：候选按相关度打分排序（原词命中标题 +3 / 正文 +2，2-gram 兜底 +0.5），并把相关度展示给模型参考。
- 理由：保证“来源发现 → 正文抽取 → 报告生成 → PDF/Word 导出”全链路可靠；打分排序让模型优先选取真正相关的报道。
- 备注：同一课题重复生成时，记忆库按 title+source 去重（新报告不再入库），属已知行为，后续可改为带时间戳标题或覆盖更新。

## D-017 科技+金融细化：领域感知选题 + 相关度打分优化

- 日期：2026-08-15
- 背景：数据源收敛为科技+金融后，实测发现：复合实体词（QQ音乐/豆包大模型）整词匹配不到标题，靠 2-gram 召回噪声大；旧新闻与专业财经源无差异化权重；选题助手无法区分科技/金融选题。
- 决策：
  1. 实体拆词（`search.py _extract_terms`）：中英/数字混合边界拆分（白敬亭GOODBAI → 白敬亭 + GOODBAI）；已知中文领域词切分（豆包大模型 → 豆包 + 大模型）；拆出的 2 字中文品类词与常见英文泛后缀（app/api/ai…）进“弱词”（命中 +0.5），纯数字子词忽略。
  2. 领域判定（`DOMAIN_TERMS` + `domain_of`）：科技/金融词表判断课题领域，选题助手在 verdict 中显示领域（科技/金融/综合/其他）并给针对性建议。
  3. 打分细化：无原词命中的纯 2-gram/弱词分数封顶 1.0；日期衰减（7 天内 ×1.2 / 30 天内 ×1.0 / 更早 ×0.5，支持 RSS pubDate 与 YYYY-MM-DD）；金融领域选题时专业财经源（第一财经/界面/21财经）+0.5。
- 理由：拆词让“豆包大模型/QQ音乐”类真实选题命中更准；日期衰减让选题助手“近期有料”判断更真实；财经源加权贴合金融选题。
- 备注：纯 2-gram 召回保留（不丢召回）只是降权；`DOMAIN_TERMS` 可持续扩充；matched 非空时 2-gram 累加不封顶属既有行为。

## D-018 领域词表文件化 + 权重 + jieba 候选生成工具

- 日期：2026-08-15
- 背景：D-017 的领域词表硬编码在代码中、无权重、覆盖有限；用户要求词表独立 JSON、权重分级，并用爬虫（不耗 token）生成候选。
- 决策：

  2. 权重语义：`domain_of` 加权投票（强 +2 / 弱 +1）；`_KNOWN_SUBTERMS` 只含强中文词参与拆词召回，弱词只参与领域判定。
  3. 新增依赖 jieba（清华镜像）；新增 `scripts/scan_domain_terms.py`：抓科技组（RSS 标题）与金融组（列表页标题），同口径 jieba 分词 + 文档频次 + log 比率判别，产出候选清单到 `docs/domain_terms_candidates.md`，人工审核后并入 JSON（不自动入库）。
- 首次审核结果（并入 7 词）：科技 agent/模型/智能体/GLM（强，2）、编程/数据（弱，1）；金融 亿元（弱，1）。智能体为 agent 的中文对应，人工补强；其余候选（新闻套话/栏目名/产品后缀）不收录。
- 理由：权重让“一票定领域”与拆词召回更准；同口径标题统计避免“标题+摘要 vs 标题”的频次失衡；候选清单可审计、可持续扩充。
- 备注：jieba 0.42.1 在 Python 3.14 有 SyntaxWarning（上游问题，不影响运行，脚本用 `-W ignore` 运行）；cnBeta RSS 偶发坏 XML（脚本已容错跳过）。
