# 决策记录（Decision Log）

格式：日期、决策编号、背景、决策、理由。新决策追加到文末；修改历史决策需新增一条并说明原因。

## D-001 模型分层

- 日期：2026-08-15
- 决策：高频机械任务（摘要/提取/整理）用 `qwen3.7-flash-2026-07-15`；规划/分析/成文/审查用 `qwen3.5-omni-plus-2026-03-15`。
- 理由：免费额度覆盖这两个模型；flash 便宜快、omni-plus 质量高；模型 ID 全部走配置文件，便于更换。

## D-002 来源可靠性：三层结构

- 日期：2026-08-15
- 决策：发现层（新闻搜索/RSS 找候选）→ 内容层（白名单域名抓正文）→ 校验层（结论必须挂原文片段+URL）。
- 理由：避免“网上随便扒两篇”；白名单保证来源可信；引用校验防幻觉。

## D-005 交互模式：阶段化 + 可中断

## D-006 网络策略：全国内、无代理

- 理由：用户环境要求；github.com 作为参考检索主源（无需代理）。

## D-007 发现层最终方案：白名单媒体 RSS 关键词检索

- 日期：2026-08-15

- 决策：发现层改为在白名单/可信媒体官方 RSS 中按关键词检索（并发抓取、标题+摘要匹配）；36氪（反爬）与虎嗅（超时）待解决后补充。
- 理由：来源可靠优先于覆盖广度；RSS 结构化、国内可达、无反爬问题。
## D-008 V3.0 长期记忆：本地知识库 + 向量检索（RAG）

- 日期：2026-08-15
- 背景：V2.0 每次分析从零开始，历史报告结论无法复用；主对话上下文有限，需要把“读过的内容”沉淀为可检索记忆。
- 决策：新增 `crawler/memory/`（`embed.py` 用 `text-embedding-v3` 生成向量；`store.py` 提供 `KnowledgeStore`，文档分块 800 字/块、100 字重叠、按句号切块，JSON 落盘 `data/knowledge/index.json`，余弦相似度检索并按文档去重）；新增工具 `search_knowledge` 并注册；V2.0 报告生成后自动入库；CLI 支持 `--stats/--index-reports/--add-file/--query`。
- 理由：JSON + 本地向量零额外服务依赖、全国内可达；报告入库后可跨会话复用结论，是长期记忆的第一版。
- 教训：分块函数曾因末块 `start` 回退写成死循环，内存被吃爆触发 `MemoryError`（终端白屏崩溃）；已修复（末块直接截断退出）并加冒烟验证。长文本处理代码必须先小样本验证终止性。
## D-009 V3.1 Web 界面：Gradio 本地服务

- 日期：2026-08-15
- 背景：开源后需要让非开发者也能用，CLI 门槛较高。
- 决策：新增 `crawler/webui.py`（Gradio 6.x），两个页签——分析报告（输入课题→进度条→渲染报告 + 文件路径 + Token 用量）与知识库检索；同时把 `orchestration.py` 的 CLI 主流程抽出为 `run_pipeline(topic, ..., progress=回调)`，CLI 与 Web 共用一条流水线。
- 理由：Gradio 纯 Python、清华镜像可装、对 AI 工作流展示友好；服务只绑定 127.0.0.1，API Key 仅存服务端 `.env`、不下发浏览器。
- 备注：取消/中断（gr.Cancelled）留待后续版本；默认端口 7860。
## D-010 V3.1 收尾：可取消流水线 + 报告下载 + 模型选择

- 日期：2026-08-15
- 决策：`run_pipeline` 增加 `cancelled` 回调（配合 `PipelineCancelled` 异常），资料收集循环与各阶段间轮询取消标志；Web 界面增加“取消任务”按钮、报告下载（`gr.File`）、收集/分析模型下拉选择。

## D-011 V3.2 报告导出：PDF / Word

- 日期：2026-08-15
- 决策：新增 `crawler/export.py`：轻量 Markdown 块解析（标题/段落/引用/有序无序列表/表格/加粗/链接）→ reportlab 渲染 PDF（优先系统微软雅黑，缺失回退内置 STSong-Light CID 字体）+ python-docx 渲染 Word（中文字体微软雅黑，链接为可点击超链接）；CLI 增加 `--export pdf,docx`，Web 界面增加“导出 PDF/Word”按钮。
- 理由：报告交付常用格式；PDF/Word 纯本地生成、零外部服务依赖；PDF 用系统字体避免在仓库捆绑大字体文件。
- 备注：PDF 链接以蓝色下划线呈现；Word 链接可点击跳转。
## D-012 验收修复：正文抽取、表格转义、导出防御与搜索排序

- 日期：2026-08-15
- 背景：V3.2 验收发现三类问题：①PDF 导出失败——标题含 `|` 导致资料清单表格列数错乱，reportlab 布局报 negative availWidth；②网页正文混入大量导航噪音，研究员难以提炼事实；③RSS 候选仅按日期排序，无关文章淹没有效结果（两次验收报告出现“无事实条目”）。
- 决策：
  1. `crawler/tools/web.py`：正文抽取优先定位内容容器（`article`/常见正文选择器），失败回退整页；
  2. `crawler/multi_agent/orchestration.py`：Markdown 表格单元格中的 `|` 转义为全角 `｜`；
  3. `crawler/export.py`：表格行归一化（补齐列数）+ 显式等分列宽，杜绝负宽度；
  4. `crawler/tools/search.py`：候选按相关度打分排序（原词命中标题 +3 / 正文 +2，2-gram 兜底 +0.5），并把相关度展示给模型参考。
- 理由：保证“来源发现 → 正文抽取 → 报告生成 → PDF/Word 导出”全链路可靠；打分排序让模型优先选取真正相关的报道。
- 备注：同一课题重复生成时，记忆库按 title+source 去重（新报告不再入库），属已知行为，后续可改为带时间戳标题或覆盖更新。
## D-013 选题助手：分析前预检 + Web 页签

- 日期：2026-08-15
- 背景：用户实测“QQ音乐/网易云/汽水音乐”话题失败——白名单媒体（科技/AI 向）不覆盖音乐流媒体领域；完整分析跑完才发现没料，浪费约 5 分钟。
- 决策：新增 `crawler/topic_check.py`（选题预检）：从课题提取实体词（按连接词切分、剔除通用词、公司前缀拆出产品名、母公司名不计相关），复用 `search_candidates` 给出“有料/偏少/没料”判定、相关候选与建议；`run_pipeline` 材料不足时输出诊断建议；Web 新增“选题助手”页签（选题指南 + 预检按钮 + 一键去生成报告）。
- 理由：把失败成本从 5 分钟降到 1 分钟；给用户明确的选题方法论（热点优先、2 对象对比、官方产品名、先预检再开跑）。
- 备注：通用词与母公司名过滤在 `crawler/tools/search.py` 实现（GENERIC_TERMS / BROAD_COMPANIES），同时提升智能体搜索质量。
